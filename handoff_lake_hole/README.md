# 交接：同一瓦片两条读取路径的"湖消失"差异定位

## 目的

同一个地块瓦片（一个外环 + 一个 4×1000 的细窄内环 = 湖），两条下游读取路径看到镜像位置，
且只有一条把湖填了。本目录提供可离线复现的证据，把三种情形区分开：

1. 只做 Y 翻转 → 位置镜像，但湖仍在；
2. 解码侧 transformer 把坐标压到更粗网格 → 内环面积变零，湖在**解码阶段**被丢弃；
3. 编码阶段就用了过粗的量化范围 → 内环在 **pbf 里已经**是零面积，任何解码参数都救不回。

## 复现

在仓库根目录（无需网络，只用本仓库的库）：

```bash
.venv/bin/python handoff_lake_hole/repro_lake_hole.py
```

产物：`tile_a_fine.pbf`（细量化，保住内环）、`tile_b_coarse_encode.pbf`（编码即粗量化的对照）。
脚本分 6 节打印证据并以断言收尾。

## 瓦片与量化配置

- 几何：外环 (512,512)-(3584,3584)；内环 x∈[2000,2004]（宽 4）、y∈[1500,2500]，extents=4096。
- 量化格宽 = 坐标跨度 / extents。要保住宽 4 的内环，格宽必须 ≤ 4：
  - 瓦片 A：`quantize_bounds=(0,0,4096,4096), extents=4096` → 格宽 1，内环完整入档；
  - 对照 B：同样的 bounds 但 `extents=512` → 格宽 8 > 4，内环在编码时塌缩。

## 机制（库内位置）

- 解码 Y 翻转：`y_coord_down=False` 时 `y = extent - y`（`mapbox_vector_tile/decoder.py:143`）。
- 解码 transformer：逐点作用于翻转后的坐标（`mapbox_vector_tile/decoder.py:146`）。
- 零面积环被静默丢弃：组环时 `_area_sign == 0` 直接 `continue`（`mapbox_vector_tile/decoder.py:176`）。
- 环层次：第一条非零面积环定外环绕向，同向开新多边形、反向作孔（`mapbox_vector_tile/decoder.py:178`）。
- 编码量化：`quantize_bounds` + `extents` 在编码前缩放取整（`mapbox_vector_tile/encoder.py:100`）；
  编码器还会丢掉零位移点（`mapbox_vector_tile/geom_encoder.py:64`），塌缩成点的环整环消失。

## 证据（脚本输出摘要）

**第 1 节 · 原始命令流（判断依据所在）**

- A raw：`MoveTo LineTo×3 ClosePath MoveTo LineTo×3 ClosePath`，2 条环；ring1 area2 = **-8000**（非零，湖在瓦片里）。
- B raw：也是 2 条环，但 ring1 只有 2 个点 `(250,324),(250,200)`，area2 = **0**（湖在 pbf 里已不存在）。
- 注意：环数都是 2，**环数不是判据，原始环面积才是**。

**第 2 节 · 瓦片 A 依次只切换 Y、只启用粗网格、再同时启用**

| 读取方式 | 环层次 | 湖 | 说明 |
|---|---|---|---|
| 默认 | Polygon，外环+内环 | 在 | 基准 |
| 只切 Y（`y_coord_down=True`） | Polygon，外环+内环 | **在** | 坐标镜像（y 1500–2500 → 1596–2596），绕向整体变号，层次不变 |
| 只启用 snap512 transformer | Polygon，仅外环 | 无 | 内环 x 2000/2004 都压到 2048 → 零面积 → 解码器丢弃 |
| 两者同时 | Polygon，仅外环（镜像） | 无 | 位置由 Y 决定，湖由 transformer 决定，互不因果 |

**第 3 节 · 对照 B 同样四种读法**：全部只剩外环，且默认读法外环是 (64,64)-(448,448)（512 网格单位），
与 A 的坐标系都不同。

**第 4 节 · transformer 本身无罪**：同一瓦片 A 用 snap2（格宽 2 ≤ 湖宽 4）读取，湖保留。
破坏性来自"网格比湖宽"，不是来自"用了 transformer"。

## 两个"无湖"样本的分步证据与正确搭配

外观同样无湖的两个样本，发生步骤不同：

- **A + snap512（解码阶段丢湖）**：raw pbf 里 ring1 面积非零（-8000）→ 湖在瓦片里，
  是 transformer 把它压成零面积后解码器按规则丢弃。修复 = 解码参数：
  去掉 snap，或把网格加密到 ≤ 内环宽度（snap2 即可），`y_coord_down` 与编码端保持一致（本例两端皆默认 False）。
- **B（编码阶段丢湖）**：raw pbf 里 ring1 已是 2 点零面积环 → 信息在编码时已不可逆丢失，
  任何解码参数组合都救不回。修复 = 编码参数：`extents` 满足 跨度/extents ≤ 最窄内环宽度
  （本例 extents ≥ 1024 是下限，取 4096 留裕量），或加宽 `quantize_bounds` 之外的量化精度。

## 两条 caution（已用实验验证）

- **不要用最终面积猜坐标阶段**：A+snap512 与 B 默认读法的最终 GeoJSON 都是"单外环、无湖"，
  面积各自自洽，无法区分丢湖发生在编码还是解码。判断依据在**原始瓦片的命令流**
  （内环面积非零 vs 已为零），最终 GeoJSON 不提供这一依据。
- **不要预设 Y 镜像会把孔填成实面**：Y 翻转让外环、内环绕向同时变号，解码器以第一条环定外环，
  孔仍是孔（第 2 节第 2 行：镜像后湖仍在）。本例中填孔的唯一机制是"环被压成零面积"。
